# Локальный ALPRProcessor

Модуль `app/services/alpr_processor.py` подключён к `vision/local` через
`ALPRPlateReader`, когда включён `VISION_ALPR_ENABLED`. Python 3.11+, NumPy, OpenCV;
для реального OCR — PaddlePaddle, PaddleOCR **3.x**, PyYAML; для SR — OpenCV contrib.
Типизированный ответ использует `typing_extensions` для совместимости с FastAPI на Python 3.11.

## Использование

```python
import cv2
from app.services.alpr_processor import ALPRConfig, ALPRProcessor

processor = ALPRProcessor(
    ocr_model_dir="/models/en_PP-OCRv4_mobile_rec",
    sr_model_path="/models/FSRCNN_x2.pb",  # необязательно; без файла SR отключён
    config=ALPRConfig(
        patterns=("DDDLLLDD",),  # пример, НЕ универсальный формат страны
        min_confidence=0.65,
    ),
)
result = processor.process_image(cv2.imread("frame.jpg"))
```

Вход — H×W×3 BGR `np.uint8`. Для RGB сначала используйте `cv2.COLOR_RGB2BGR`.
Один экземпляр создаётся при старте процесса; вызовы защищены блокировкой.
Исходное изображение не изменяется. Не изменяйте его из другого потока во время вызова.

Ответ содержит ровно:

```json
{"plate_text": "123ABC01", "confidence": 0.91, "warp_image_base64": "..."}
```

`warp_image_base64` — PNG 470×110, без префикса `data:image/png;base64,`.
Это исходный выровненный кроп, до усиления резкости, пригодный для ручной проверки.
Нет пластины: пустые строки и 0. Пластина найдена, но чтение отклонено:
пустой текст, 0 и непустой кроп. Невалидный массив вызывает `ValueError`;
ошибка модели/детектора — `ALPRError`. Неверные локальные пути при старте
вызывают `FileNotFoundError`/`ValueError`. Сбой одной OCR-ветки допускается;
сбой всех веток поднимает ошибку. В журнал записывается количество сбоев без номера.

## Как обрабатывается кадр

1. OpenCV уменьшает только копию для поиска, находит выпуклые четырёхугольники
   по контурам и фильтрует их геометрию. Координаты возвращаются в исходный масштаб.
   Ограничены размер входа, разрешение поиска, число контуров и кандидатов.
2. Четыре угла упорядочиваются; `getPerspectiveTransform` и `warpPerspective`
   формируют прямоугольник 470×110. OCR проверяет до пяти кандидатов.
3. Если задан SR-файл и дисперсия лапласиана ниже порога, OpenCV DNN запускает
   FSRCNN x2. Алгоритм и масштаб обязаны совпадать с весами; поддержаны также
   ESPCN/EDSR x2/x3/x4. Ошибка SR не скрывается заменой на обычное масштабирование.
4. Из одного изображения независимо создаются LAB L/CLAHE, HSV V/adaptive Gaussian
   и bilateral + unsharp. Три варианта передаются одному OCR последовательно:
   это ансамбль независимых обработок, а не три копии модели в памяти.
5. Выбирается максимальный исходный `rec_score` среди допустимых результатов всех
   веток и кандидатов. Confidence не повышается из-за совпадений или исправлений.

## Алфавит и исправления

У [PaddleOCR TextRecognition](https://github.com/PaddlePaddle/PaddleOCR/blob/main/docs/version3.x/module_usage/text_recognition.en.md)
нет аргумента EasyOCR `allowlist`. Адаптер использует `model_dir` и `predict`;
результат читается через `rec_text`/`rec_score`. Словарь берётся из экспорта модели.
**Здесь реализована строгая проверка выхода, а не маскирование логитов декодера.**
Если требуется именно 36-классовый словарь при декодировании, нужен совместимый
экспорт модели, обученной с таким словарём, или собственный `Recognizer` с
ограниченным декодером. Подмена словаря чужой модели меняет соответствие индексов
символам и недопустима.

Разрешены только ASCII A–Z/0–9, строчные буквы переводятся в верхний регистр,
пробелы и дефисы удаляются. Другие символы отклоняют всю строку, а не исчезают
незаметно. Кириллические двойники не транслитерируются.

`patterns=()` по умолчанию отключает позиционные догадки. В шаблоне D означает
цифру, L — букву, X — любой разрешённый символ. Только при несовпадении типа
позиции применяются O↔0, I↔1, B↔8, S↔5, Z↔2. Среди подходящих шаблонов выбирается
требующий меньше замен; если разные ответы требуют одинакового количества замен,
чтение отклоняется. Указывайте только допустимые для вашей задачи форматы.

## Модели и окружение

Перед запуском самостоятельно поместите доверенные веса в локальную директорию.
Для OCR нужен экспорт Paddle с `inference.yml`, `inference.pdiparams` и
`inference.json` либо `inference.pdmodel`. Имя архитектуры берётся из
`Global.model_name` в `inference.yml`. Подходит английская модель распознавания
текстовых строк; встроенный детектор текста Paddle не используется.
Веса не включены в репозиторий. Код не скачивает их и отключает проверку
доступности источников моделей PaddleX до импорта PaddleOCR. Для строгого
офлайн-развёртывания запретите исходящий трафик контейнера на уровне сети.

Установка для **отдельного окружения**, не поверх существующего backend:

```sh
python -m pip install paddlepaddle==3.2.2 paddleocr==3.3.2 numpy \
  opencv-contrib-python==4.10.0.84 fastapi uvicorn pillow pyyaml typing_extensions
```

Основные версии проверены в локальном Linux/Docker, но это не полный lock-файл
транзитивных зависимостей. PaddleX 3.3 проверяет имя дистрибутива и отклоняет
headless-замену, поэтому ALPR-образ содержит `opencv-contrib-python` и `libgl1`/
`libgomp1`; графический интерфейс при распознавании не используется. В итоговом
образе оставлен **один** пакет, предоставляющий `cv2`. Основной backend использует
`opencv-python-headless`; просто добавить contrib рядом нельзя. Порядок замены
показан в `Dockerfile.alpr`.

## FastAPI и Docker

### Запуск в основном интерфейсе ScanAgro

```sh
docker compose build api
docker compose -f docker-compose.yml -f docker-compose.dev.yml -f docker-compose.alpr.yml up -d --build
```

Открыть `http://localhost:8000/ui/`. Дополнительный compose включает ALPR в API и
worker, использует отдельный образ `fable-backend:alpr` и проверяет веса через
`scripts/fetch_alpr_models.py`. Веса закреплены по SHA-256; скачивание происходит
только на этапе подготовки. Данные, галерея эталонов и PostgreSQL остаются в томах.

На вход ALPR поступает кроп от действующего YOLO-детектора номера. Для него
уточняются углы, выполняются три обработки и PaddleOCR. Если нет подходящих углов,
номер двухстрочный или новый обработчик не принял текст, используется прежний
CCT/PP-OCR. Ошибки выполнения модели не скрываются. В карточке результата движок
нового чтения обозначается `paddleocr_alpr`. Ранее сохранённые результаты не
пересчитываются автоматически: нажмите «Обработать заново».

Для возврата к прежнему образу: `docker compose -f docker-compose.yml
-f docker-compose.dev.yml up -d --no-deps api worker` (одной строкой).

### Отдельный пример API

Готовый пример — `examples/alpr_api.py`: модель создаётся через lifespan, CPU-работа
выполняется в thread pool, тело ограничено 10 MiB, размер JPEG/PNG проверяется
до декодирования. Ошибки преобразуются в 400/413/415/422/503.

```sh
export ALPR_OCR_MODEL_DIR=/models/en_PP-OCRv4_mobile_rec
export ALPR_SR_MODEL_PATH=/models/FSRCNN_x2.pb
uvicorn examples.alpr_api:app --host 127.0.0.1 --port 8081 --limit-concurrency 4
curl -H 'Content-Type: image/jpeg' --data-binary @frame.jpg http://127.0.0.1:8081/recognize
```

В PowerShell переменные задаются через `$env:ALPR_OCR_MODEL_DIR='C:\models\...'`.
Для Docker копируйте `app/services/alpr_processor.py` и `examples/alpr_api.py`
с сохранением структуры; монтируйте `/models` read-only, задайте переменные выше.
В контейнере слушайте `0.0.0.0`, снаружи публикуйте порт на `127.0.0.1`.
Одна модель на процесс: число uvicorn workers умножает расход памяти.
Для подключения к существующему FastAPI перенесите создание экземпляра в его
lifespan; пример не содержит авторизации и предназначен для локальной интеграции.

## Проверка и ограничения

```sh
python -m pytest tests/test_alpr_processor.py tests/test_alpr_api.py -q
```

Тесты используют настоящие операции OpenCV на синтетическом кадре и подставной
OCR/SR: геометрия и PNG, автоматический поиск углов, ансамбль, несколько кандидатов,
порог, шаблоны, сбои, локальные пути и ограничения API. Это не оценка точности
PaddleOCR на реальных номерах и не проверка конкретных весов SR.

При подключении 18.09.2026 прошли 67 тестов ALPR и интеграции. Отдельно выполнен
`scripts/check_alpr_runtime.py` в Docker с `--network none`: настоящий PaddleOCR
и FSRCNN прочитали синтетический `123ABC10`. Контрольная загрузка реального снимка
через основной API завершилась с моделью `local-alpr-paddle-v2` и движком
`paddleocr_alpr`. Это smoke-проверки работоспособности, не замер точности на выборке.

Контурный детектор — ограниченный базовый вариант: при сильном размытии границы
пропадают, а прямоугольные вывески могут давать ложные кандидаты. Для промышленной
сцены подключайте обученный детектор пластин через `CornerDetector.detect(image)`.
Он должен возвращать список массивов `(4, 2)` в исходных координатах. Обычный
YOLO bbox не даёт четыре перспективных угла: нужны keypoints/segmentation либо
уточнение границ внутри bbox. Здесь YOLO-веса не требуются и не скачиваются.

Поддерживаются однострочные пластины, без переворота на 180°. Двухстрочные требуют
отдельного разбиения строк. Confidence — оценка OCR, а не вероятность правильности
всего ALPR. Даже высокий score и соответствие формату не доказывают наличие номера.
SR может придумывать детали; порог размытия и качество SR необходимо измерить
на вашей выборке (exact match, ложные чтения, доля отказов, p95 latency).
Необратимо утраченные символы алгоритм надёжно восстановить не может.

API [OpenCV DNN SuperRes](https://docs.opencv.org/4.11.0/d8/d11/classcv_1_1dnn__superres_1_1DnnSuperResImpl.html):
локальный `readModel`, выбор алгоритма через `setModel`, выполнение `upsample`.
