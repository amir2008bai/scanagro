# Доработка по PROMPT_FOR_ASTRA6 — 17.09.2026

Сохранены FastAPI, PostgreSQL, очередь, API и три адаптера распознавания.
Обучения моделей, подстановки символов номеров и снижения порогов не было.

## Что изменилось

1. **Контекст вокруг техники.** Эталоны из исходных кадров и запрос к галерее
   расширены на 30% ширины и 10% высоты с каждой стороны. Политика записана
   в `crop_policy.json` и в манифест индекса; API, подготовка эталонов и оценка
   используют одну функцию. Рамки объектов и изображения для чтения номеров
   и шильдиков не расширяются. Старый индекс без политики продолжает работать
   в прежнем режиме.
2. **Кириллица.** Добавлены PP-OCRv3 Cyrillic и словарь с URL, SHA-256 и Apache-2.0
   в реестр весов. Сессия кешируется на процесс. Переключатель
   `VISION_CYRILLIC_ATTRIBUTES=true`; отключение оставляет прежнее чтение надписей.
   Дополнен словарь КАМАЗ, МАЗ, ГАЗ, УРАЛ, КРАЗ, БЕЛАРУС, МТЗ, КИРОВЕЦ.
   Неоднозначное МАЗ по-прежнему не принимается за марку.
3. **Сбои распознавания.** Полный отказ всех OCR-движков теперь завершает задание
   ошибкой, вместо ложного успешного результата «текст не найден».
   Работающий резервный движок остаётся допустимым. Ошибки загрузки OCR шильдиков
   также больше не скрываются.
4. **Проверка весов.** `fetch_models.py --check-only` больше не удаляет повреждённый
   файл. При загрузке замена происходит только после проверки новой копии.
   Исправлено название региона 16: East Kazakhstan.

## Проверка до/после

Все 25 фотографий обработаны реальными локальными моделями на CPU, без внешнего API.
Исходная разметка сохранена. JSON с каждым кадром и сводками лежит в:
`eval/astra6_before`, `eval/astra6_after`,
`eval/astra6_reference_before`, `eval/astra6_reference_after`.

| Показатель | До | После |
| --- | --- | --- |
| Найдены рамки номеров на кадрах с номером | 15/15 | 15/15 |
| Полное совпадение читаемых номеров | 7/7 | 7/7 |
| Ошибки символов на читаемой части | 0 | 0 |

| Ложное принятие на нечитаемых кадрах | 0/10 | 0/10 |
| Правильный тип, исключая ту же физическую машину из эталонов | 20/24 | 21/24 |
| Ошибочный тип / отказ | 1 / 3 | 0 / 3 |
| Правильно определённая марка / ошибочная марка | 3/10 / 0 | 3/10 / 0 |
| Среднее время полного OCR-прогона | 10.45 с | 10.69 с |

Время — наблюдение этого запуска, не чистый бенчмарк: часть проверки типов и тестов
выполнялась одновременно. Проверка номеров и проверка галереи запускаются отдельными
скриптами. Время OCR-прогона не включает галерею. Ни принятые номера, ни сырой текст
номеров не изменились ни на одном из 25 кадров.

Изменения по проблемным кадрам:

- **14:** отказ → верный `trailer`.
- **13:** ошибочный `trailer` → отказ `classes_too_close`.
- **4 и 8:** остаются неоднозначными; ответа галереи нет.
- **19:** кириллица читает «СТАЙЕР», но это декоративная надпись. В исходной разметке
  стоит KAMAZ. Приписывать STEYR было бы новой ошибкой; текст сохраняется как evidence.
- **5, 15, 23:** мелкий/стилизованный «КИРОВЕЦ» модель пока не читает надёжно.
  Улучшения метрики марок нет; модель и тип трактора не выдумываются по надписи.

Предварительная абляция, `eval/context_ablation.json`: расширять только запрос
дало 20 верных / 0 ошибок / 4 отказа; запрос и эталоны — 21 / 0 / 3;
склеивать исходный и контекстный embeddings — 20 / 0 / 4. Выбран второй вариант.
Для повторения `eval/probe_context.py --baseline-gallery <путь>` нужен индекс из
исходных, ещё не расширенных эталонов Opus.

## Что намеренно осталось открытым

**Двухстрочные номера.** Нашёл официальный документ: пункт 16
[правил регистрации сельхозтехники](https://old.adilet.zan.kz/rus/docs/V1500011702)
отсылает к СТ РК 1176. Достоверную таблицу геометрии и расположения символов самого
стандарта в открытом виде не получил. Поэтому `provisional` у существующих двухстрочных
форматов не снят, порог не снижен. Кадры 4 и 9 по-прежнему не принимаются как полный номер.

**Две буквы не обязательно означают пропуск.**
[Официальные образцы](https://old.adilet.zan.kz/rus/docs/V1500012892) отдельно
описывают знаки физических и юридических лиц. Нельзя считать текущую ограниченную
грамматику исчерпывающим стандартом и автоматически вставлять `?` в `597AQ10`.
Нужна независимая проверка разметки и образцов корпоративных номеров. В этом изменении
приём таких строк не включён, существующие отказы сохранены, пояснения исправлены.
Частичная строка с угаданным количеством/местами неизвестных символов не добавлена;
доступны исходный `plate_text_raw`, кандидаты OCR и причины отказа.

**Обобщение.** Здесь только одна камера, 7 читаемых номеров и 24 размеченных типа.
Leave-one-machine-out исключает указанные в разметке совпадения машин, но одинаковый
фон камеры остаётся. Выбор контекста проверялся на этой же малой выборке: это результат
на предоставленных данных, а не независимая оценка будущей точности. Нужны новые камеры,
машины и кадры; отсутствие ошибок здесь не означает готовность к любым условиям.

## Запуск и обновление

Для нового развёртывания используйте README: генерация `.env`, затем Docker Compose.
Новые веса скачиваются через существующий `fetch-models`, проверяются по SHA-256;
новая галерея создаётся из обновлённого `reference_seed`.

Для локального запуска из `backend`:

```bash
python scripts/fetch_models.py
python scripts/build_reference_gallery.py --dir data/reference_new --seed-from reference_seed
python eval/evaluate.py --photos ../photos --out eval/check_plates
python eval/evaluate_reference.py --photos ../photos --dir data/reference_new --out eval/check_types
```

На существующем сервисе **не удаляйте рабочий том**. Подготовьте отдельную галерею,
добавьте свои эталоны с такой же политикой кадрирования, постройте индекс, переключите
`VISION_REFERENCE_DIR` и перезапустите worker (индекс кешируется). В Compose путь задан
в `environment`, поэтому одного изменения `.env` для этого недостаточно. Само обновление
образа не перезаписывает уже заполненный том эталонов. Нельзя просто дописать новую
политику в старый индекс без повторного кадрирования и построения.

Источники новых весов: [реестр RapidOCR](https://github.com/RapidAI/RapidOCR/blob/main/python/rapidocr/default_models.yaml),
[PaddleOCR, Apache-2.0](https://github.com/PaddlePaddle/PaddleOCR/blob/release/2.7/LICENSE).
URL, размер, версия и SHA-256 обоих артефактов находятся в `model_registry.py`.

Проверки: PostgreSQL 16, миграции до `0004_vehicle_type_provenance`, `alembic check`,
pytest, Ruff, проверки файлов моделей; подробный итог записан в `eval/astra6_validation.txt`.
