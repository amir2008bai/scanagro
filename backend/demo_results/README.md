# Настоящий прогон 25 фотографий

Результаты обработки присланных фотографий через **HTTP API и отдельный Docker worker** с
провайдером `local`. Это выполненное распознавание на открытых моделях, а не mock и не
заранее записанные ответы: тот же код обрабатывает любую новую фотографию.

Воспроизвести:

```bash
python scripts/process_directory.py ../photos --out my_results
```

## Сводка прогона

25 фотографий, 25 заданий завершено, **0 ошибок**. Обнаружено 38 объектов техники и 21
номер; 7 номеров приняты как прочитанные, сохранено 40 фрагментов до и после выравнивания.
`is_mock=false`, provider `local`, model `local-alpr-v1` на всех кадрах.

## Что здесь лежит

| Файл | Содержимое |
| --- | --- |
| `results.json` | Полный экспорт: техника, номера, отдельные координаты номера, четыре угла, три уверенности по этапам, причина отказа |
| `results.csv` | То же в плоском виде для таблиц, с BOM для Excel |
| `summary.json` | Сводка прогона |
| `manifest.json` | Соответствие исходных файлов и `image_id` |
| `annotated/` | 25 JPEG с рамками: техника — красным, номер — зелёным (прочитан) или янтарным (не прочитан), четыре угла — синим. Для компактности архива пережаты в quality 85; сервис отдаёт их в 92 |
| `plates/` | 40 фрагментов номеров **до** и **после** исправления перспективы |

## Как читать результаты

`license_plate` заполнен только тогда, когда чтение совпало с известным форматом
Казахстана. Уверенное, но структурно невозможное чтение попадает в `plate.text_raw`, а
`plate.status` объясняет отказ. Так `597AQ10` — две буквы там, где формат требует три —
виден целиком, но не выдаётся за подтверждённый номер. На разметке такой номер обведён
янтарным с подписью `unreadable (597AQ10)`.

Ложные срабатывания детектора номеров тоже сохраняются: например, надпись `KAMAZ` на
решётке радиатора попадает в `extra.additional_plates` с `text_raw` и причиной отказа. Так
видно, что система нашла, и почему это не стало номером.

Три уверенности разделены: `vehicle_confidence` (детектор техники),
`plate.detection_confidence` (детектор номера) и `plate.ocr_confidence` (измеренная по
посимвольным вероятностям). Чёткая рамка вокруг нечитаемого номера и размытая рамка вокруг
читаемого — разные ситуации.

`model` пуст на всех кадрах: ни на одной фотографии не видно обозначения модели. Это
корректный ответ, а не пробел.

`vehicle_type_source` показывает, что решило тип: `reference_gallery` — совпадение с
эталонной фотографией, `badge_text` — надпись на машине, `detector` — грубый класс COCO,
в котором **нет сельхозтехники**, поэтому такой ответ доверия почти не заслуживает. На
разметке тип из галереи помечен `~`.

Важная оговорка про эти конкретные результаты: галерея эталонов собрана из этих же 25
кадров, поэтому близость здесь завышена (совпадение с самим собой). Честные числа считаны
с исключением кадра из индекса и лежат в `../eval/reference_results/`.

## Метрики

Разобраны в [../RESULTS.md](../RESULTS.md) с явными знаменателями: 7 полностью читаемых
номеров, 8 частично читаемых, 10 кадров без читаемого номера. **7 кадров с одной камеры не
доказывают универсальную точность.**

## Идентификаторы

`image_id` и `detection_id` относятся к базе того прогона. После нового запуска они не
обязаны существовать в вашей базе.
