# Fable Backend

Обновление 17.09.2026: [исправления по промпту Astra и результаты до/после](ASTRA6_REVIEW.md).

Бэкенд сервиса для обнаружения техники, чтения государственных номеров и определения типа, производителя и модели по фотографиям. Это доработанный исходный проект: сохранены FastAPI, SQLAlchemy, PostgreSQL, Alembic, маршруты `/api/v1` и отдельный адаптер распознавания.

Распознавание выполняется **локально, на открытых моделях, без платного API и без внешнего endpoint**. Провайдер `local` объединяет RT-DETRv2 (техника), YOLOv9 (номерной знак), перспективное выравнивание на OpenCV и два OCR-движка — fast-plate-ocr и PP-OCR. Веса скачиваются по фиксированным URL и проверяются по SHA-256.

Остаются доступными прежние режимы: `mock` (пустой результат, только для проверки цепочки) и `openai_compatible` (ваш собственный мультимодальный сервер). Названия Astra-6/Fable/Opus из переписки не считаются существующими адресами или идентификаторами API.

Тип техники определяется поиском по галерее эталонных фотографий: в COCO нет класса сельхозтехники, поэтому «Кировец» и МТЗ иначе приходят как `truck`. Эталоны добавляются папками, без переобучения — **[docs/REFERENCE_GALLERY.md](docs/REFERENCE_GALLERY.md)**.

Компоненты, лицензии, метрики и ограничения: **[docs/RECOGNITION.md](docs/RECOGNITION.md)**. Результаты на 25 присланных фотографиях: **[RESULTS.md](RESULTS.md)**.

## Быстрый запуск

Нужны Docker Engine/Desktop с Compose и Python 3.12+ для создания конфигурации.

```bash
python scripts/init_config.py
docker compose up --build -d
docker compose ps
```

Скрипт создаёт `.env` со случайными ключом API и паролем БД. Существующий `.env` он не перезаписывает. В архиве рабочих секретов нет.

При первом запуске сервис `fetch-models` скачивает веса (~115 МБ) в том `model_cache` и сверяет контрольные суммы. `api` и `worker` стартуют только после его успешного завершения, поэтому они никогда не работают с недокачанным файлом. Нужен исходящий HTTPS — **только в первый раз**; дальше том уже прогрет и сервис завершается сразу. Веса намеренно не встроены в образ: они большие и версионируются отдельно от кода.

Требования к оборудованию: **2 ядра CPU, 2 ГБ RAM для worker, ~1 ГБ на диске**. GPU не нужен и не предполагается. Одна фотография 2688x1520 обрабатывается за 5–19 с на CPU (оба OCR-движка), в среднем 8–9 с; разброс зависит от числа найденных объектов и загрузки машины. Подробности и способ ускорения — в [docs/RECOGNITION.md](docs/RECOGNITION.md).

- Swagger: http://localhost:8000/docs
- Проверка готовности БД и хранилища: http://localhost:8000/api/v1/health
- Проверка процесса API: http://localhost:8000/api/v1/health/live
- В Swagger нажмите **Authorize** и вставьте значение `API_KEY` из `.env`.

Compose запускает PostgreSQL, однократную миграцию, API и отдельный worker. API доступен только через loopback `127.0.0.1`; база наружу не опубликована. Данные лежат в постоянных томах `postgres_data` и `image_storage`. Обычные `restart` и `docker compose down` данные сохраняют. Команда `down -v` удаляет тома — не используйте её для рабочей базы.

Остановка: `docker compose stop`. Логи: `docker compose logs --tail=100 api worker`.

## Режимы распознавания

### `local` — открытые модели на вашем железе (по умолчанию)

```dotenv
VISION_PROVIDER=local
VISION_MODEL_DIR=./data/models
VISION_DEVICE=cpu
```

Вне Docker веса нужно получить самостоятельно:

```bash
python scripts/fetch_models.py
```

Скрипт скачивает и проверяет по SHA-256 всё, что перечислено в
`app/services/vision/local/model_registry.py`, и прогревает кэши библиотек, которые
качают веса сами. `--check-only` проверяет уже скачанное и возвращает ненулевой код при
расхождении.

Основные настройки (полный список с пояснениями — в `.env.example`):

| Переменная | Значение | Смысл |
| --- | --- | --- |
| `VISION_DEVICE` | `cpu` \| `cuda` \| `auto` | Для `cuda` нужен `onnxruntime-gpu`; на GPU не тестировалось |
| `VISION_MAX_PARALLEL_IMAGES` | `1` | Сколько фотографий одновременно внутри пайплайна. Именно это ограничивает пиковую память, а не число моделей |
| `VISION_USE_PPOCR` | `true` | Выключение ускоряет обработку примерно втрое ценой измеримого падения точности |
| `VISION_VEHICLE_INPUT_SIZE` | `960` | На 640 теряется удалённая техника |
| `VISION_OVERLAY_BAND_TOP` | `0.045` | Верхняя полоса с меткой времени камеры; `0` отключает |
| `VISION_REFERENCE_GALLERY` | `true` | Определение типа техники по эталонам; `false` отключает этап |
| `VISION_REFERENCE_DIR` | `./data/reference` | Папка с эталонами; пустая папка просто отключает этап |
| `VISION_REFERENCE_MIN_MARGIN` | `0.04` | Требуемый отрыв от второго класса. Ниже — больше ответов и больше ошибок |

Масштабируйте числом процессов worker, а не ростом `VISION_MAX_PARALLEL_IMAGES`: сессии
ONNX общие на процесс, а промежуточные тензоры — нет.

### `openai_compatible` — ваш внешний мультимодальный сервер

В `.env` укажите параметры вашего сервера:

```dotenv
VISION_PROVIDER=openai_compatible
VISION_BASE_URL=http://host.docker.internal:8001/v1
VISION_API_KEY=
VISION_MODEL=actual-served-vision-model-id
```

Сервер должен поддерживать `POST /v1/chat/completions` с изображением в `messages[].content[].image_url` в формате data URL. Текстовая модель без поддержки изображений не подходит. `VISION_BASE_URL` включает `/v1`, но не `/chat/completions`. Для локального запуска вне Docker используйте адрес, доступный с вашего компьютера, например `http://localhost:8001/v1`.

Если сервер не поддерживает `response_format: {"type":"json_object"}`, установите `VISION_USE_RESPONSE_FORMAT=false`. Остальные параметры запроса (`temperature`, `max_tokens`, multimodal messages) должен поддерживать сервер. Ошибки 401/403/400 не маскируются успешным пустым результатом и не повторяются автоматически. Для временных ошибок сети, 429 и некоторых 5xx предусмотрены ограниченные повторные попытки с задержкой.

```bash
docker compose up -d --force-recreate api worker
```

Конфигурация читается при старте процесса. В очереди сохраняются provider и model задания; адрес и ключ берутся из текущей конфигурации. Перед сменой адреса сервера завершите очередь или остановите приём новых загрузок. Нельзя гарантировать точность OCR, марки/модели и координат без проверки выбранной модели на размеченной выборке.

По умолчанию для запроса модели изображение уменьшается с сохранением пропорций до стороны 2560 px. Для мелких номеров можно увеличить `VISION_MAX_IMAGE_SIDE` в пределах возможностей модели. Координаты результата нормализованы в `[0, 1]` и относятся ко всему изображению. Неуверенные марка, модель и номер должны быть `null`; значение `confidence` приходит от модели и не является измеренной вероятностью точности.

## API для будущего интерфейса

Для всех операций с изображениями, заданиями, результатами и экспортами нужен заголовок `X-API-Key`. Исключения: корень, документация и health endpoints. Это ключ доверенного клиента/одной команды; отдельных пользователей, ролей и изоляции организаций пока нет. При создании публичного интерфейса потребуется пользовательская авторизация; сервисный ключ нельзя вшивать в публичный JavaScript.

| Метод и путь | Назначение |
| --- | --- |
| `POST /api/v1/images?process=true` | Multipart-поле `files`, загрузка одного или нескольких файлов и постановка заданий |
| `GET /api/v1/images?limit=50&offset=0` | Список изображений |
| `GET /api/v1/images/{id}` | Метаданные изображения |
| `GET /api/v1/images/{id}/file` | Нормализованное изображение |
| `GET /api/v1/images/{id}/annotated` | JPEG с текущими объектами и подписями |
| `POST /api/v1/images/{id}/process` | Повторная обработка, ответ 202 с заданием |
| `DELETE /api/v1/images/{id}` | Удаление изображения, связанных заданий и объектов |
| `GET /api/v1/jobs?image_id={id}&status=completed` | Список заданий с фильтрами и пагинацией |
| `GET /api/v1/jobs/{id}` | Статус и безопасное сообщение об ошибке |
| `GET /api/v1/detections` | Поиск по `image_id`, `vehicle_type`, `manufacturer`, `license_plate`; `limit/offset` |
| `GET /api/v1/detections/{id}` | Один объект |
| `PATCH /api/v1/detections/{id}` | Правка атрибутов, `bbox` и/или `plate_bbox`, с обновлением изображения разметки |
| `DELETE /api/v1/detections/{id}` | Удаление объекта и обновление разметки |
| `GET /api/v1/exports/results.json` | Результаты JSON |
| `GET /api/v1/exports/results.csv` | CSV с BOM для Excel |

В Windows используйте `curl.exe`, если `curl` является псевдонимом PowerShell.

```bash
curl -H "X-API-Key: YOUR_KEY" -F "files=@photo.jpg" http://localhost:8000/api/v1/images
curl -H "X-API-Key: YOUR_KEY" http://localhost:8000/api/v1/jobs/JOB_UUID
curl -X PATCH -H "X-API-Key: YOUR_KEY" -H "Content-Type: application/json" \
  -d '{"license_plate":"123 ABC 01","plate_readable":true}' \
  http://localhost:8000/api/v1/detections/DETECTION_UUID
```

Задания проходят состояния `pending → processing → completed/failed`. При аварии процесса незавершённое задание можно повторно захватить после истечения lease (по умолчанию до 360 секунд). Количество захватов ограничено `JOB_MAX_ATTEMPTS`. Вызов внешней модели при аварии может повториться; запись результата защищена от устаревших workers. Гарантируется согласованная публикация результата, а не «ровно один» запрос к внешней модели.

Пока для изображения есть активное задание, повторная обработка, удаление изображения и ручные исправления возвращают **409**. Неудачная повторная обработка сохраняет предыдущие результаты. Успешная повторная обработка заменяет их, включая ручные правки. История заданий сохраняется, история всех версий объектов — нет.

### Что добавилось в ответах

Имена и форма прежних полей сохранены. К каждому объекту добавлено:

| Поле | Смысл |
| --- | --- |
| `vehicle_confidence` | Уверенность детектора техники. `confidence` сохранён и дублирует её |
| `manufacturer_confidence` | Уверенность OCR по надписи, по которой определён производитель |
| `source_label` | Исходный класс детектора до сопоставления с нашим словарём |
| `vehicle_type_source` | Что решило тип: `reference_gallery` \| `badge_text` \| `detector` \| `manual`. **`detector` означает грубую догадку COCO** |
| `vehicle_type_confidence` | Уверенность того этапа, который решил тип |
| `plate.bbox` | **Координаты номера — отдельно от координат техники** |
| `plate.quad` | Четыре угла номера, если геометрия их восстановила |
| `plate.detection_confidence` | Уверенность детектора номера |
| `plate.ocr_confidence` | Измеренная по посимвольным вероятностям уверенность чтения |
| `plate.text_raw` | Лучшее сырое чтение — сохраняется и тогда, когда номер отклонён |
| `plate.format`, `plate.region` | Распознанный формат и регион Казахстана |
| `plate.ocr_engine`, `plate.ocr_variant` | Какой движок и какое преобразование дали принятый результат |
| `plate.rectified`, `plate.perspective_skew` | Использовалось ли выпрямление и насколько велика перспектива |
| `plate.status` | Почему номер принят или отклонён |
| `plate.crop_filename`, `plate.rectified_crop_filename` | Фрагменты до и после выравнивания |

Три уверенности разделены намеренно. Чёткая рамка вокруг нечитаемого номера и размытая
рамка вокруг читаемого — разные ситуации, и потребитель должен их различать.

**Номер объявляется прочитанным только при совпадении с известным форматом Казахстана.**
Уверенное, но структурно невозможное чтение (`597AQ10` — две буквы там, где формат требует
три; метка времени камеры) попадает в `plate.text_raw` со `status`, а `license_plate`
остаётся пустым и `plate_readable=false`. Символы никогда не достраиваются и не
исправляются. Подробности — в `docs/RECOGNITION.md`.

В `PATCH` отсутствие поля сохраняет значение. `manufacturer`, `model`, `license_plate`, `confidence`, `plate_bbox` можно сбросить через `null`; `vehicle_type`, `plate_readable`, `bbox` — нельзя. Правка `plate_bbox` сбрасывает машинные `plate_quad`, `plate_perspective_skew` и `plate_detection_confidence`: оператор сообщает, что модель смотрела не туда. Правка текста номера сбрасывает `plate_ocr_confidence` и сведения о движке — значение пришло от человека, и оценка модели его больше не описывает. Непустой `license_plate` автоматически означает читаемый номер, если флаг не передан явно; `plate_readable=false` очищает номер. Пустой номер с `plate_readable=true` отклоняется.

Коды ошибок: 400 — повреждённый файл/неверная форма, 401 — ключ API, 404 — объект или файл отсутствует, 409 — активное задание, 413 — превышение лимита, 415 — неподдерживаемый/несоответствующий формат, 422 — неверные параметры, 507 — недостаточно места. Неожиданные ошибки возвращают 500 и `request_id`; секреты и ответы модели клиенту не выдаются.

## Изображения и экспорт

JPEG, PNG и WEBP проверяются по фактическому содержимому. Анимация и многостраничные файлы отклоняются. Проверяется полное декодирование, размер файла, размер запроса, число файлов и число пикселей. EXIF-поворот применяется перед сохранением, прозрачность сводится к белому фону, EXIF/GPS/XMP удаляются. `/file` отдаёт **нормализованную копию**, а не исходные байты; `sha256` и `file_size` относятся к ней. Храните собственные оригиналы отдельно, если они нужны.

При ошибке одного файла обычная пакетная загрузка откатывается целиком. Файлы пишутся через временные имена и атомарную замену. После аварии или неоднозначного COMMIT возможны сиротские файлы; сборщик мусора описан в `docs/OPERATIONS.md`. Удаление файла после успешной транзакции может быть отложено, если файл занят.

Экспорт содержит `status`, `latest_job_id`, `result_job_id`, `provider`, `recognition_model`, `is_mock` и `error_message`. Так пустой результат распознавания отличим от необработанного изображения, сбоя и тестового режима. При провале повторной обработки `result_job_id` указывает на предыдущий успешный результат. JSON читается в согласованном снимке БД.

Можно повторять фильтр `image_id`: `?image_id=UUID1&image_id=UUID2` (до 100 значений). Максимум без пагинации — 1000 изображений по умолчанию; для больших выборок используйте `limit/offset`. CSV защищает текстовые ячейки от выполнения формул префиксом `'`; JSON сохраняет значения без этой модификации. Имена полей и форма основных ответов исходного API сохранены; добавлены служебные поля.

## Обработка папки задания

Распакуйте `photos.zip` или используйте `/data/Auto`. На машине, где запускается скрипт, установите зависимости:

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate
# Linux/macOS: source .venv/bin/activate
python -m pip install -r requirements.txt
# Установите API_KEY из .env в переменную окружения вашего терминала.
python scripts/process_directory.py /data/Auto --out results
```

Пример PowerShell без вывода ключа:

```powershell
$env:API_KEY = (Get-Content .env | Where-Object { $_ -like 'API_KEY=*' }) -replace '^API_KEY=', ''
python scripts/process_directory.py 'C:\data\photos' --out results
```

Скрипт загружает файлы по одному, ожидает задания с общим тайм-аутом и сохраняет только изображения своего запуска: `manifest.json`, `results.json`, `results.csv`, `summary.json`, `annotated/*.jpg`. При сбое отдельного задания сохраняет результаты и завершает работу с кодом 1. При сетевом сбое повторите команду с `--resume`; сохранённые IDs не загружаются заново. Если сервер принял загрузку, но ответ потерялся до записи manifest, повторная отправка может создать копию: API не объявляет загрузку идемпотентной. `--recursive` включает подкаталоги.

В `demo_results/` лежат результаты **настоящего** прогона всех 25 присланных фотографий провайдером `local`: `results.json`, `results.csv`, изображения с рамками и фрагменты номеров до и после выравнивания перспективы. Предыдущие mock-результаты заменены. `sample_output.json` — только пример формата.

Метрики и честные знаменатели — в [RESULTS.md](RESULTS.md), разметка — в `eval/ground_truth.json`.

## Локальная разработка без Docker для API

Запустите PostgreSQL 16 отдельно. Создайте `.env`, настройте `DATABASE_URL` на свою БД и установите зависимости как выше.

```bash
python -m alembic upgrade head
python -m uvicorn app.main:app --reload
```

При `PROCESSING_MODE=inprocess` API запускает ограниченное число обработчиков той же очереди PostgreSQL. Для отдельного процесса выставьте `PROCESSING_MODE=worker` и дополнительно запустите `python -m app.worker`. Создание таблиц на старте API не используется — применяйте миграции.

Распознавание, выбор компонентов, лицензии и ограничения: `docs/RECOGNITION.md`. Эталоны и определение типа техники: `docs/REFERENCE_GALLERY.md`. Тесты, ограничения проверки и список исправлений: `AUDIT_AND_TESTS.md`. Публикация, обновление, резервные копии и очистка: `docs/OPERATIONS.md`. Схема приложения: `docs/ARCHITECTURE.md`.
